# DEPS 增强依存关系交稿求解器

语料组只交每句获准保留的普通词和必要的增强依存关系（DEPS）。本工具在
普通词顺序、新词号、基本 HEAD 均已确认的前提下，决定：

1. 哪些原 DEPS 关系可以保留（只允许沿用原关系并按已批准的节点对应改编号，
   绝不新增没有原依据的边）；
2. 不能交原文字段的中间原词，用许可里的哪个 CoNLL-U 空节点占位；
3. 如何保证固定检查器查询（两个准交普通词 + 允许的依存标签序列，问原图是否
   存在匹配的有向路径）在交稿图上的答案与原图完全一致。

## 核心约束的处理方式

- **合并产生新路径**：两个原位置即使都能使用同一个空节点编号，也会检查
  合并后的整图效果。一旦合并让某个原答案为“否”的查询变为可达，则该共享
  分配被拒绝（见 `s_merge` 示例）。
- **误删真实路径**：对每个原答案为“是”的查询，保留其原图所有见证路径的
  边集作为可行性下界，任何删边使全部见证消失的分支立即剪枝。
- **空节点行数最少**：外层按“占用不同空节点行数”升序枚举角色分配，首个
  可行预算即最优；同预算下保留的原关系数最大化。
- **并列方案**：同样省的结果只交一份，manifest 的 `ties` 列出其余方案实际
  使用的角色分配与原关系编号（1-based）。
- **不可行**：许可内不存在交稿时，该句不产生数据行，manifest 给出哪些查询
  与哪些许可节点无法同时容纳（端点合并的 yes 查询、合并后新可达的 no 查询），
  其他句子照常输出。

## 输入 bundle 格式

一个 JSON 文件，顶层为 `{"sentences": [...]}`，每句字段：

| 字段 | 含义 |
| --- | --- |
| `sent_id` | 句子 id |
| `conllu` | 原 CoNLL-U 文本（含增强 DEPS）；省略时只产出关系清单，不产出交稿 |
| `id_map` | 已确认的原词号 → 交稿词号（只含准交普通词） |
| `hidden_roles` | 不能交原文字段的中间原词（含被撤行的原空节点）id |
| `license` | `空节点id -> [可承载的原角色id...]` |
| `placeholder_rows` | 可选，每个占位行的字段模板（form/lemma/upos/xpos/feats/head/deprel/misc） |
| `basic_override` | 可选，基本 HEAD/DEPREL 的确认改法（默认跟随 `id_map` 翻译） |
| `queries` | 检查器查询：`name, source, target, labels`，端点用原词号 |

原关系编号规则：按句中词序遍历，跳过多词词段行，每个词 DEPS 列内按序列化
顺序从 1 编号。manifest 用该编号报告每条采用/舍弃的关系。

## 运行

```bash
python -m deps_redaction.cli bundle.json deliverable.conllu manifest.json
```

- `deliverable.conllu`：可被 pyconll 重新读取的交稿（不可行句只输出状态注释）。
- `manifest.json`：每句的采用/舍弃原关系编号、占位行与其承载的原位置、
  查询答案对照、并列方案与不可行诊断。
- 退出码：全部可行返回 0，存在不可行句返回 2。

## 算法

对每句：

1. 枚举隐藏角色到许可空节点的全部分配，按占用行数升序；
2. 固定分配后，每条原边确定性映射为一条候选交稿边（重复边合并并记录全部
   原索引）；
3. 对候选边做保留/舍弃的深度优先搜索，剪枝条件：
   - 当前边集已让某个 no 查询变为可达；
   - 剩余边无法再覆盖任一 yes 查询的任意见证路径；
4. 完整候选图本身满足全部查询时直接采用（保留关系最多的快路径）。

搜索设 50 万节点上限；超限的分配在诊断中标记为需人工复核，不会静默产出。
