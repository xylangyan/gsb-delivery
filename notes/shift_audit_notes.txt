Pre-work shift audit (shiftaudit) - design notes
=================================================

Scope
-----
Add a pre-work check on top of the stock parsedatetime English setup so one
collection machine can never hold two paper orders over one real time
interval.  parsedatetime itself is untouched; shiftaudit only calls
Calendar.evalRanges / Calendar.parse and interprets the results.

Pipeline per candidate offset (engine.ScheduleAuditor.evaluate_order)
---------------------------------------------------------------------
1. shifted real UTC anchor = batch anchor (UTC) + candidate integer seconds.
2. local wall-clock anchor = shifted UTC instant converted with the zone
   handed to the audit only; the host timezone is never consulted.
3. evalRanges(note, local anchor) with time.localtime frozen to the machine
   clock value preserved from the original run, so leftover notes that
   cannot establish a date reproduce that run instead of reading today.
4. the two returned local wall clocks are converted back to real UTC
   instants through the same zone, classifying each end as unique / fold /
   gap.  Repeated fall-back clocks use the work-order tie (earlier ->
   fold 0, later -> fold 1); a spring-forward gap, or a repeated clock
   without a tie rule, is a missing wall-clock cell and is unbookable.
5. real-time intersection uses left-closed/right-open UTC intervals.

Reproduced stock-library quirks (verified in tests/TestShiftAudit.py)
---------------------------------------------------------------------
- "tomorrow 9-11pm then 7:45-8:15" books the next-morning 07:45-08:15
  window; the evening text in front of "then" is discarded.
- "August 29 - September 2, 2006" makes both ends inherit the anchor's
  hour/minute/second.
- Leftover text the range regex does not cover makes evalRanges re-parse
  the remainder; when that parse has no date/time the source anchor is
  dropped and the machine clock is read.  The engine mirrors the same
  regex/context decision (_leftover_loses_anchor) and freezes the clock.
- flag 0 has two shapes: machine-clock passthrough (clock_fallback) vs.
  source anchor passthrough for a recognised but impossible window
  (not_a_range, e.g. "25:00-26:00").
- Reversed windows ("5-3pm", "September 5 - August 3, 2006",
  "11:30pm-12:30am") come back inverted; old orders have no automatic
  overnight rollover, so every start >= end is unbookable.
- The CRE_TIMERNG sub-range form "August 1-15, 2006" even rolls the year
  forward when the month already passed; it is treated like any other
  library output rather than normalised.

Offset search and history handling
----------------------------------
- Anchor batches are recorded as (start UTC, integer-second step, count)
  and generated by plain second arithmetic, so month and year boundaries
  cross naturally (AnchorBatch.anchors).
- Each route keeps only the distinct local wall-clock anchors its batches
  imply; fall-back can collapse two UTC instants onto one wall clock.
- evalRanges is a pure function of (note, local anchor); each distinct
  pair is evaluated once and memoised.  The offset sweep therefore never
  replays the cartesian product of candidates and historical anchors -
  repeated shift shapes cost one parse regardless of how many offsets or
  batch entries repeat them.
- The two routes never merge order ids; collisions carry both route ids.

Verdicts and inspection
-----------------------
- An offset is bookable iff every order on every route is bookable and no
  two bookings on the same device overlap in real UTC time.
- Collisions sort by real collision start, then by the original order id.
- For any offset, explain_offset returns the per-order real UTC anchor,
  the local anchor handed to evalRanges, the actual UTC ranges taken from
  the paper, and the wall-clock classification (unique/fold/gap) acting at
  each end; merged_device_ranges joins touching same-device segments.
