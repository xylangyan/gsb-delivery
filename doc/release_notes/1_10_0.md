# 1.10.0

## Features

### `:digest_auth` plugin: `auth-int` and `Authentication-Info` verification

The `:digest_auth` plugin now supports the `auth-int` quality of protection. The
entity hash is calculated over the encoded request payload (after form and
multipart encoding and content coding, and before any transfer encoding), so the
peer verifies exactly the bytes it receives.

Requests replayed after a challenge (including stale-nonce rounds) resend the
same entity bytes. Payloads which cannot be produced twice (one-shot enumerators,
multipart parts delivered late) are staged once to a temporary file and replayed
from there.

When the peer responds with an `Authentication-Info` header, its `rspauth` is
verified against the response entity and the authorization round that was
actually sent, including when the header arrives in trailers. A `nextnonce` from
a verified response is used for the next request in the same authentication
space, so subsequent pages do not need another probe.

A request body which cannot be staged, or whose size does not match its declared
`content-length`, fails the request explicitly instead of being signed with a
digest that represents only part of the payload.

Peers which only advertise `qop="auth"` keep the previous behavior.
