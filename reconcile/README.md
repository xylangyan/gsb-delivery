# 签收差异单最小标记求解器

两份日结（旧账、新账）里都有内容完全相同的短行，直接用
`patiencediff.PatienceSequenceMatcher` 做差异时，这些重复行会被按位置
配对，可能配错。本求解器在**不改动任何原行文字**的前提下，给部分原行
附上一个比对标记，让每张签收视图的原生 Patience 结果满足档案员已确认
的配对（必须在内）和禁配对（必须在外），并使实际附标记的原行数量最少。

## 判定模型

- 每行的比对键是 `(原行文本, 标记)`；未附标记时标记为 `null`。
- 两行相等当且仅当原行文本相同，且双方标记相同（任一侧附了标记而另一
  侧没有，或标记值不同，都不相等；标记永远不能跨越不同的原行文本）。
- 一行至多附一个标记，且该标记对包含该行的所有视图全局生效；标记值只
  能取自该行 `allowed_tags` 中获准的原字段值。
- 视图是原行的有序子序列，顺序与原账一致；每张视图仍调用仓库现有的
  `patiencediff.PatienceSequenceMatcher` 取原生匹配块，块内逐行配对即
  为该视图的实际配对结果。
- 允许两行同值却不配对（各自作为新增/移除），求解器不强制配对，只校验
  已确认关系在内、禁配关系在外。

## 输入 JSON

```json
{
  "old_rows": [
    {"id": "old-1", "text": "待领", "allowed_tags": ["批号B1"]}
  ],
  "new_rows": [
    {"id": "new-3", "text": "待领", "allowed_tags": ["批号B1"]}
  ],
  "views": [
    {
      "name": "全账",
      "old": ["old-1"],
      "new": ["new-3"]
    }
  ],
  "confirmed": [["old-1", "new-3"]],
  "forbidden": [["old-1", "new-1"]]
}
```

- `old_rows` / `new_rows`：固定原行号、原行文本、该行获准使用的字段值。
- `views`：每张视图只列入选行的原行号，旧侧、新侧各自保持原顺序。
- `confirmed`：档案员核实过、必须出现在对应视图原生配对中的关系。
- `forbidden`：档案员圈出、绝不能被自动配到一起的关系。

## 运行

```
.venv/bin/python -m reconcile.solver reconcile/examples/batch_instance.json
.venv/bin/python -m reconcile.solver 实例.json -o 报告.json
```

## 输出语义

- `status = "optimal"`：存在唯一的最省标记方案（按各视图原生配对结果
  衡量），`tags_by_original_row` 即交给档案员的原行号 → 标记清单。
- `status = "ambiguous"`：同样数量的最省标记会让某张视图的未签行被配到
  不同位置。`ambiguous_views` 逐张附上该视图的**两份真实原生结果**及各自
  的示例标记，不自动认同任何一条，需人工裁决。
- `status = "infeasible"`：没有共同标记可行。`blockers` 指出具体卡点：
  已签关系原行文本不同、某视图内已签关系交叉或共行（违反 Patience 的单
  调一一配对）、单视图无解，或各视图单独可行但共享行要求互斥的全局标记。

## 算法要点

- 按“附标记原行数”迭代加深（0、1、2……），第一个可行预算即最小值，廉
  价解不会被零标记分支的指数枚举淹没。
- 每张视图的 Patience 结果按“该视图内已附标记行的局部配置”缓存；长账
  多视图反复使用同一批原行时，同一局部配置只跑一次原生比对，不按全局
  标记组合整账重跑。
- 视图内可标记行一旦全部决策完即提前校验并剪枝；已定型且键不等的已签
  关系、结构性交叉/共行关系直接判死。
- 最省解按“全部视图原生配对签名”去重，只保留产生不同原生结果的方案，
  避免等价标记组合膨胀。
