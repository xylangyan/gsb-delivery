# Holding-library wordlist archival pipeline

A small pycldf pipeline that merges supplier wordlists into a readable CLDF
Wordlist and then re-archives the result under a new catalogue edition. It
exists to make citation routing auditable when the same short code means
different things in different numbering contexts.

## Numbering model

Three layers are kept strictly separate; resolution is always driven by
manifests and mapping tables, never by the shape of a code string.

1. **Stable holding id** — the library item, e.g. `R37`, `R88`.
2. **Supplier local code** — meaningful only inside that batch's own mapping
   table. Alpha's `X1` and beta's `AB` both denote holding `R37`, while beta's
   raw `X1` denotes `R88`. The same string in ordinary prose/comment fields is
   never treated as a citation.
3. **Catalogue official code** — edition dependent. Catalogue edition 1 made
   the official code of `R37` literally `X1`; edition 2 replaced that official
   code with `CAT37` (`R88`: `X2` -> `CAT88`).

The resolution chain is:

```
supplier local code -> per-batch mapping -> holding id -> catalogue official code
```

Stage 2 has two chains in one run:

```
edition-1 official code -> holding id -> edition-2 official code   (finished artifact)
supplement local code   -> per-batch mapping -> holding id -> edition-2 official code
```

Because the edition-1 artifact already uses official codes, its `X1` is never
sent through a batch mapping; the supplement's raw `X1` is. Each therefore
lands in its own bibliography entry.

## Layout

- `holdingcldf/` — pipeline package
  - `catalog.py` — catalogue editions, per-batch mappings, batch manifests
  - `references.py` — CLDF `Key[description]` parsing/rewriting (order and
    bracket descriptions preserved)
  - `cldf_builder.py` — pycldf Wordlist construction and read-back through the
    CLDF `source` property columns
  - `pipeline.py` — `build_edition_one` / `rearchive_edition_two`
  - `provenance.py` — `archive_manifest.json` and `HANDOFF.md`
  - `errors.py` — structured `RefProblem` / `ArchiveError`
  - `cli.py` — command line entry point
- `data/` — fixture inputs: two catalogue editions, two batches, one raw beta
  supplement, one missing-target input, one two-candidate input
- `tests/` — pytest suite
- `artifacts/` — produced CLDF datasets (regenerated by the commands below)

The word-form table and example table use distinct local citation column
names (`Witness_Ref`, `Example_Ref`); both are declared with the CLDF
`http://cldf.clld.org/v1.0/terms.rdf#source` property and `;` separator.

## Running

```bash
# Stage 1: readable edition-1 CLDF
python -m curation.holdingcldf.cli edition1 \
  --output curation/artifacts/wordlist-edition1 \
  --batch curation/data/batches/batch_alpha \
  --batch curation/data/batches/batch_beta \
  --catalog curation/data/catalog/edition1 \
  --library curation/data/source_library.tsv

# Stage 2: re-archive with the raw beta supplement under catalogue edition 2
python -m curation.holdingcldf.cli edition2 \
  --output curation/artifacts/wordlist-edition2 \
  --edition-one curation/artifacts/wordlist-edition1 \
  --supplement curation/data/supplement_beta \
  --catalog curation/data/catalog/edition2 \
  --library curation/data/source_library.tsv
```

Re-running stage 2 onto the same output path is safe (staging directory plus
atomic swap). Passing an edition-2 artifact as `--edition-one` is refused with
`wrong numbering context` and writes nothing.

## Guarantees

- One BibTeX entry per holding; keys are the official codes of the declared
  catalogue edition.
- All citations are read back from the actual CLDF source columns after
  writing and compared cell-by-cell against the intended rewrite; order, page
  ranges (`3-5`), sections (`Appendix A`) and repeated citations are retained.
- No half-updated output: every citation is validated first; problems are
  collected, and files are only written to a staging directory that is swapped
  into place on success.
- Errors name the batch, original field, table row number/ID, raw reference
  and either the missing target or both mapping candidates.
- Which numbering context an artifact lives in is recorded in
  `archive_manifest.json` (`numbering_context`) and explained in `HANDOFF.md`;
  key string shape is explicitly not evidence of the context.
